How it works

Scan it. Check it. Move it.

The whole workflow is built around one rule: the plan is always visible before anything is written to disk.

1

Scan your new media files

Runs in the background and reads only. Every video file is classified as movie, series episode, or skip (samples, extras, trailers, files still arriving), and a destination path is resolved for each keeper.

move new downloads scan
2

Review the report

A grouped report shows source → target for every file, with move / replace / skip actions. Anything the matcher is unsure about is flagged suspect so you look twice. Anything already fixed is marked corrected.

get move new downloads scan report
3

Fix what’s wrong

Wrong folder? Hit Browse…, search every library at once, pick the right show folder — the server rebuilds the season folder and episode filename for you, even across a series → movie → series round-trip.

update move new downloads scan
4

Confirm the move

Moves run in the background with live progress (phase, speed, file %). Cross-drive copies go through a .partial file so interrupted moves never leave half files. Jellyfin rescans the touched libraries when done.

Why it’s nice

Built for real libraries

The details that matter when you have thousands of files and zero patience for misplaced episodes.

Review-first moves

Every run produces a plan with per-file actions. Confirm the whole plan or just a few items — by ID, exact path, or folder prefix.

Suspect & corrected flags

Low-confidence matches are badged suspect; every retarget or auto-correction is badged corrected with a note explaining what changed.

Browse & retarget

One combined “All libraries” browser with instant search. Pick a folder and the server recomputes season dirs, episode tags, and movie names.

Queued confirms

Hit confirm while a move is running and your batch waits in line instead of being rejected — then starts automatically.

History with undo

Every confirm is stored as a group with full source → target rows. Move a file again to a better home, or undo a group to put files back.

Live move progress

Watch phase, bytes copied, speed, and per-batch totals. Multi-batch confirms report per-batch counts, never cumulative mush.

Jellyfin integration

Lists libraries, triggers whole-library or per-item scans, and notifies Jellyfin about exactly the paths that changed.

Release tracker

Stores “next episode expected on …” markers for ongoing shows, so you can ask what’s due before re-checking the library.

Skips in-progress files

Files still being written are detected by on-disk markers (.part, .!qB, …) and skipped — no extra integration needed.

API

Talk to it however you like

# Start a scan of your new media files
curl -X POST localhost:18328/scans \
  -H 'Content-Type: application/json' \
  -d '{"replaceExisting": true}'

# Poll until completed, then read the plan
curl localhost:18328/scans/current/progress
curl localhost:18328/scans/current/report

# Move the files
curl -X POST localhost:18328/scans/{scan_id}/confirm
# List tools
curl -X POST localhost:18328/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# Scan your new media files
curl -X POST localhost:18328/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call",
       "params":{"name":"move new downloads scan",
                 "arguments":{"replaceExisting":true}}}'

The Web UI uses the same native /api/* routes — no MCP round-trip. Set UI_PANEL_PASSWORD to put the panel behind login, JELLYSORT_MCP_TOKEN to gate /mcp.

FAQ

Fair questions

Will it move my files without asking?

No. Scanning only ever builds a plan. Files move when you confirm — the whole plan or just the items you pick.

What if a file lands in the wrong show folder?

Retarget it from the report with Browse… — the server fixes the season folder and filename. Corrections are badged so you can see what changed.

My libraries are on different drives. Problem?

No — cross-drive copies stream through a .partial file with live progress, so an interrupted move never leaves a half file behind.

Does it touch files that haven't finished arriving?

No. In-progress files are detected by their on-disk markers and skipped automatically.

Is this page the app?

No — this is the static overview. The actual app (scan → review → confirm panel) runs at / on your own host, and this same page is served at /website on the service port.
